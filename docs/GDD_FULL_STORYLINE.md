## 1. 游戏概述

| 项目 | 内容 |
|------|------|
| **游戏名称** | 齿轮黎明 |
| **英文副标题** | Dead Hour |
| **核心标语** | 一年。一座城市。一根中指上的伤口。 |
| **类型** | 文字冒险 · 分支叙事 · 生存模拟 |
| **主角** | 喻城（Yù Chéng）——职校机械系，23岁 |
| **时间跨度** | 第0天前48小时开始，共365个游戏日 |
| **结局数量** | 16个主线结局 + 1个隐藏结局 + 死亡成就系统 |
| **基调** | 文学惊悚 · 硬科幻异变 · 工业生存美学 |

### 1.1 核心承诺

这个游戏管理的不是资源，而是一个刚好也在管理资源的人。

所有机制系统——感染值、防御指数、倒计时、科技树——存在的意义是制造叙事压力，而非供玩家优化。游戏的胜利条件是活下来。游戏的**意义**在于你在这个过程中变成了什么。

### 1.2 叙事框架——见证者日志

游戏以喻城手写的一段话开场：

> *「我不知道有没有人会读到这里。但如果你读到了，说明这本笔记本最终没有和我一起消失。」*
>
> *「下面的内容，是我从第一天开始写下的。我尽量写得准确，不夸张，不美化。」*
>
> *「感染值这个词是裴嘉应教我的。她说，给它命名，比不给它命名，好控制一点。」*

这个框架在整个游戏中持续存在。在时间跳跃的平静日子里，若 `wrote_journal = true`，玩家读到的是喻城的第一人称手写日志，而非旁白摘要。

**二周目继承机制：** 若上一周目触发了特定结局，本页开头会出现一行被铅笔划掉的文字。划掉的力度很重，但依然可以辨认。

## 2. 核心系统参考

### 2.1 数值系统总览

| 数值 | 范围 | 玩家可见 | 默认值 | 归零后果 |
|------|------|---------|--------|---------|
| `health` 生命值 | 0–20 | ✓ | 10 | 结局：`ending_death_health` |
| `morale` 士气 | 0–20 | ✓ | 10 | 结局：`ending_death_morale` |
| `leadership` 领导力 | 0–20 | ✓ | 0 | — |
| `stealth` 潜行 | 0–20 | ✓ | 0 | — |
| `trust` 信任 | 0–20 | **信号提示** | 5 | 派系崩溃事件 |
| `infection` 感染值 | 0–10 | **信号提示** | 0→1（scene_101触发） | 结局：`ending_full_zombie` |
| `will` 意志值 | 0–10 | **信号提示** | 5 | 同士气归零 |
| `security` 防御指数 | 0–100 | ✓ | 0 | 危机场景触发 |
| `timeRemaining` 倒计时 | 0–12 | ✓ 倒计时 | 12 | 触发危机场景 |

### 2.2 感染值信号阈值

```
infection 0–2   → 无任何提示
infection 3–4   → 文本提示：「右手中指隐约有些不对劲，说不上来是什么。」
               → 解锁：异化视角（低级）
infection 5–6   → 文本提示：「皮下那种感觉越来越难以忽视。」
               → 状态面板出现：感染 · 扩散中
               → 解锁：异化视角（中级）+ 超频操作
infection 7–8   → 文本提示：「某些念头出现的方式开始让你感到陌生。」
               → 状态面板：感染 · 异变临界
               → 自动设置 flag: zombie_turning
               → 解锁：镜中第三人机制
infection 9     → 文本提示：「边界在模糊。你已经不确定，某些念头，是不是你自己的。」
infection 10    → 自动设置 flag: full_zombie → 立即触发 ending_full_zombie
```

### 2.3 意志值信号阈值

```
will >= 8 AND infection 3–7  → 自动设置 flag: superpower_awakening
                             → 状态面板：意志 · 觉醒临界
will <= 2                    → 状态面板：意志 · 濒临崩溃
will = 0                     → 触发士气崩溃（同士气归零结局）
```

### 2.4 ✨ NEW — 意志值完整补充与消耗表

**v2.0问题**：意志值在超频、镜中人等机制中大量消耗，但日常循环中没有明确的补充途径，导致数值单向递减成死胡同。

**v2.1修正**：将意志值定义为「人对自身的清醒认知与掌控感」。每当喻城做出一件他能控制的事，意志会恢复；每当他感知到自己失控，意志会下降。

**补充途径（白天/黄昏阶段）：**

| 行动 | will变化 | 附加效果 | 条件 |
|------|---------|---------|------|
| 休息（Rest） | +1 | health +1, morale +2 | 任何阶段 |
| 写日志（Write journal） | +1 | — | `wrote_journal = true` |
| 与裴嘉应深谈 | +2 | trust +1 | `pei_alive = true`，黄昏阶段 |
| 成功修好一件物品 | +1 | morale +1 | 黄昏·改装工坊，成功触发 |
| 阅读技术手册（搜刮找到） | +1 | morale +1 | 特殊物品触发 |
| 帮助NPC解决难题 | +1 | trust +1 | 外交行动成功 |

**消耗途径（明确列出供参考）：**

| 触发 | will变化 |
|------|---------|
| 超频操作（金属直感） | -1/次 |
| 超频操作（感知共鸣） | 无（但infection +2） |
| 镜中第三人·选项B（继续观察） | 无（但infection +1） |
| 镜中第三人·不处理直接关闭 | -2 |
| 裴嘉应对峙（失去控制感） | -2 |
| 目睹NPC死亡 | -2 |
| 深夜感染梦境（未抵抗） | -1 |

**设计意图**：意志值的补充必须来自「主动掌控」，而非被动恢复。这确保了选择「超频压榨自身」的玩家必须通过「深度对话/修缮物品/写作」来维持平衡——这些也是人物性格最核心的行为。

### 2.5 ✨ NEW — 信任值（trust）信号系统

**v2.0问题**：trust完全隐藏，归零导致暴毙时玩家毫无预警，产生强挫败感。

**v2.1修正**：与infection/will一样，trust通过**NPC对白和场景描述**外化信号，而非通过UI数字显示。

**信号规则（StatPanel不显示trust数字，但场景文本会变化）：**

| trust范围 | NPC行为信号 | 场景文本特征 |
|----------|------------|------------|
| 15–20 | NPC主动帮你留门、主动分担劳动、闲聊时提到你的名字 | 「老许说，他今天帮你把那根管子提前焊好了。」 |
| 10–14 | 正常合作，完成任务，没有额外主动性 | 对白平实，无特殊温度 |
| 5–9 | 对白变得公式化，眼神开始躲闪，对你的指令有轻微迟疑 | 「他回答了你的问题，但没有看你。」 |
| 3–4 | 状态面板出现：信任 · 不稳定。你能听到隔壁房间压低的声音。 | 「你路过储物间时，谈话声停了一下。」 |
| 1–2 | 状态面板：信任 · 崩溃临界。某个NPC明显在回避和你单独相处。 | 「阿福今天没有出现在早饭桌上。」 |
| 0 | 触发「派系崩溃」事件，自动进入特定场景 | 冲突、背叛、或大规模出走事件 |

**代码层面**：在 `StatPanel.tsx` 中新增 trust 信号，对应 `LL.statSignal.trust.*` 键。

**设计意图**：信任从未变成一个可以看见的数字——但玩家能感知它的存在。如果他们没有注意到这些信号，那是他们的选择，而不是游戏的隐瞒。

### 2.6 防御指数标签

```
0–19    → 不设防
20–49   → 基础加固
50–79   → 相当安全
80–100  → 钢铁要塞  ← 若 zombie_turning = true，「反锁」讽刺结局可触发
```

### 2.7 变异路线判定

每次场景跳转后自动评估：

| 路线 | 条件 |
|------|------|
| `survivor` 幸存者 | infection < 3，或 infection < 5 且 will >= 6 |
| `awakening` 觉醒 | infection 3–7 且 will >= 8 |
| `turning` 异变 | infection >= 8 |
| `zombie` 完全异化 | infection = 10 |

### 2.8 ✨ NEW — 资源数学闭环

**v2.0问题**：机械厂（无农业）和防空洞（无农业）接收12名幸存者后，每日需要8单位食物，但文档没有说明这两个据点如何提供足够的食物来源。农场是唯一有农业的据点，这使得选择其他两个据点后收留幸存者等同于宣判死刑。

**v2.1修正**：定义搜刮产出基准和各据点专属食物获取机制。

**搜刮产出基准（每次白天·外出搜刮行动）：**

| 阶段 | 团队规模 | 食物产出/次 | 水产出/次 | 备注 |
|------|---------|-----------|---------|------|
| 第一阶段（Day 1–90） | 独行 | 2–4 | 2–3 | 城市物资尚未被大规模搜刮 |
| 第二阶段（Day 91–180） | 小型（2–5人） | 4–6 | 4–5 | 附近区域开始枯竭 |
| 第三阶段（Day 181–270） | 中型（6–10人） | 3–5 | 2–4 | 旱灾导致水源-30% |
| 第四阶段（Day 271–365） | 围攻中 | 1–3 | 1–2 | 围攻期外出风险大，产出-50% |

**各据点专属食物机制（弥补无农业的缺口）：**

| 据点 | 专属机制 | 日产出上限 | 触发条件 |
|------|---------|----------|---------|
| **机械厂** | 货车扩大搜刮范围 | +3食物/天 | `truck_key_found = true` + 燃料物品 |
| **机械厂** | 工业废料换取食物 | +1食物/天 | Tier 2科技——收音机信号放大器建好后，与有农业的中立幸存者组进行以物换物 |
| **防空洞** | 应急广播交换网络 | +2食物/天 | `npc_lian_yu_recruited` + Tier 1紧急广播发射机 |
| **农场** | 农业直接产出 | +5食物/天 | `npc_a_fu_recruited` + Tier 1作物轮作系统 |

**生存可行性验证（接收12名幸存者后，大群消耗8食物/天）：**

| 据点 | 搜刮（平均/天按每2天一次） | 专属机制 | 总日均 | 缺口 |
|------|--------------------------|---------|--------|------|
| 机械厂（有货车） | 2.0 | +3 | 5.0 | -3（需仔细管理） |
| 机械厂（无货车） | 2.0 | +1 | 3.0 | -5（高风险，不建议大规模收留） |
| 防空洞 | 2.5 | +2 | 4.5 | -3.5（需要以物换物补充） |
| 农场 | 1.5 | +5 | 6.5 | -1.5（最可持续） |

**设计结论**：机械厂和防空洞的大规模群体依然有挑战性，但不再是数学上的必败局。玩家需要在Day 241「楼道里的求救声」到来前，已经建立了相应的专属食物机制，否则收留确实风险极高——这本身就是一个合理的设计压力，而非Bug。

### 2.9 ✨ NEW — 领导力（leadership）提升途径与信号系统

**设计意图**：领导力是一项需要玩家主动投资的隐藏数值。它不显示在状态面板上，但通过NPC行为和场景文本外化。选择专注改装、搜刮或潜行路线的玩家自然不会积累它——这是有意为之的代价，而非疏漏。

**信号规则（StatPanel不显示leadership数字，但场景文本会变化）：**

| leadership范围 | NPC行为信号 | 场景文本特征 |
|---------------|------------|------------|
| 0–4 | NPC自行决定小事，不来征询你的意见 | 「老许已经把那根管子换掉了。他没有问你。」 |
| 5–9 | NPC开始在模糊情况下等待你表态 | 「连珏看了你一眼，没有先开口。」 |
| 10–14 | 状态面板出现：领导力·初具威信。NPC在分歧时主动寻求你的裁定 | 「两个人都停下来，看着你。」 |
| 15–19 | 状态面板：领导力·核心支柱。NPC在危机中第一时间找你，而非自行处理 | 「阿福跑来找你，而不是连珏。这是第一次。」 |
| 20 | 状态面板：领导力·不可或缺。派系谈判中对方首先询问你的立场 | 「林嘉雯说，她想先听你说。」 |

**提升途径（需主动选择，非自然积累）：**

| 行动 | leadership变化 | 条件 | 可用阶段 |
|------|--------------|------|---------|
| 在NPC分歧中主动裁定并执行结果 | +2 | 需两名以上NPC在场且意见相左 | 第二阶段起 |
| 外交行动成功（说服中立幸存者加入） | +2 | 外交行动判定通过 | 第二阶段起 |
| 收留楼道里的求救者（Day 250） | +2 | 选择收留12名幸存者 | 第三阶段 |
| 在派系谈判中代表群体发言 | +2 | `has_group = true`，派系接触场景 | 第三阶段起 |
| 里程碑围攻事件中稳定群体士气 | +3 | morale >= 10 且围攻事件选择「公开讲话」 | 第四阶段 |
| 帮助NPC解决个人危机（非任务性） | +1 | NPC专属事件触发，玩家选择介入 | 全阶段 |
| 郑博士救援成功后主导研究整合 | +2 | `scientist_saved = true`，主导决策选项 | 第三阶段 |

**消耗与惩罚：**

| 触发 | leadership变化 |
|------|--------------|
| 在群体面前使用超频且被目击 | -2 |
| 派系谈判破裂（因玩家选择强硬立场） | -2 |
| 拒绝收留楼道里的求救者（Day 250） | -3 |
| trust归零触发派系崩溃事件 | -4 |
| 裴嘉应被挟持时选择「放弃」 | -3 |

## 3. 新增机制详解

### 3.1 超频操作（Overclocking）

**设计理念：** 感染值不是被动积累的惩罚数值，而是可以主动支出的危险资本。

**触发条件：** `infection >= 5` 且 `superpower_awakening = true`

**超频类型与代价：**

| 超频类型 | 感染值代价 | 效果 | 风险 |
|----------|-----------|------|------|
| 血肉焊接 | infection +1 | 防御指数 +30，耗时归零 | 若infection因此达到8，自动触发zombie_turning |
| 心率扫描 | infection +1 | 探查门后情况 | will -1 |
| 金属直感 | will -1 | 物品获取量+50% | 无infection代价 |
| 感知共鸣 | infection +2 | 感知大范围尸群位置 | 极高风险，偶尔触发「白大褂」存在感 |

每次使用超频，若 `wrote_journal = true`，当日日志有一行用不同力度写下的字：

> *「今天我用了。不得不用。结果是对的。」*
> *（下面有什么被划掉了，划了很多次。）*

### 3.2 裴嘉应的笔记本——实时互动机制

详见[第12章：裴嘉应笔记本插值模板规范](#12-裴嘉应笔记本插值模板规范)（v2.1新增章节，解决了v2.0中组合爆炸问题）。

**核心规则**：
- 笔记本条目通过**行为原子+语气修饰符**拼接生成，而非为每种行为组合独立写文本
- 玩家可通过偷看（stealth >= 4）、消耗trust、或裴嘉应主动出示来获取
- 内容根据前1–3天的实际行为动态生成

### 3.3 异化视角（Depraved Insight）

**触发条件：** `infection >= 3`

**三个级别：**

| 级别 | 解锁条件 | 能感知的信息 |
|------|---------|------------|
| 低级感知 | infection >= 3 | 门后生物数量、大致移动状态 |
| 中级感知 | infection >= 5 | 具体位置、心跳节律、是否为变异个体 |
| 高级感知 | infection >= 7 且 superpower_awakening | 可感知「白大褂」的存在及其注意力方向 |

**叙事规则**：异化视角的文字风格始终是技术性、冷静的，不使用恐怖小说语言。

### 3.4 垃圾佬改装系统（Junk Collector）

**可搜集的工业废料：**

| 物品 | 获取途径 | 堆叠上限 |

#### 第三阶段（第181–270天）：科学家

**v2.1新增——裴嘉应的自救暗号机制（The Industrial Signal）**

**v2.0问题**：被挟持时的救援选项（付赎金、领导力谈判、超频、放弃）过于工具化，削弱了她作为「清醒观察者」的主动性。

**v2.1修正**：若在被挟持前已积累足够的关系深度，她会主动留下只有喻城能读懂的工业暗号。

**触发条件：** `trust >= 12` 且 `pei_knows_infection = true`（她知道喻城的感染情况）

**暗号内容**：她用手术刀在金属器物表面刻下一系列线条和角度符号——这是建筑结构图纸中的应力标记语言，喻城作为机修工能够识别其含义。

**解读内容（仅在满足条件时场景中呈现）**：

> *你蹲下来，盯着那道划痕看了很久。*
>
> *不是随意的抓挠。是应力标注符号——45度斜线表示「左侧」，三个等号表示「三层」，一个指向上方的箭头旁边画了一个三角形：「高处，等待」。*
>
> *她知道你能读懂这个。她知道你一定会来找她。*
>
> *她没有写「救我」。她写的是方向。*

**暗号救援选项**：玩家可使用「读取暗号路线」选项，获得精准位置信息，stealth成功率大幅提升，且不需要支付赎金或消耗领导力。

**未触发时**（trust < 12 或 pei_knows_infection = false）：救援选项退回原始四选项（赎金/谈判/超频/放弃），没有暗号线索。

**叙事意义**：这不是她无助等待——这是她对喻城的判断，她确信他会来，确信他能读懂。她的主动性被保留，而玩家是否能接收到这份信任，取决于他们是否建立了足够深的关系。

#### 第四阶段（第271–365天）：变量

## 5. 日常循环设计

### 5.1 四段式游戏日

```
清晨（情报与结算）
  → 计算前一晚资源消耗（食物、水）
  → 应用日常感染值变化（被动基础变化：见2.2节）
  → 若 pei_alive：解算裴嘉应前一天的行为原子（见第12章）
  → 收音机广播（若物品栏有收音机）——包括派系线索广播（见6.4节）
  → 若 wrote_journal = true：生成当日日志卡

白天（主行动轮）← 玩家选择点
  → 【建造/加固】    security变化，时间消耗
  → 【外出搜刮/推进主线】  获取物品，健康风险，场景事件
  → 【外交/研究】    trust变化，NPC关系，Flag推进
  → 【改装工坊】     消耗废料，制造装备（3.4节）
  → 【休息】         health +1, morale +2, will +1，风险最低  ← v2.1新增will恢复

黄昏（整备阶段）
  → 自动计算食物与水的分配
  → 改装操作（若材料足够且相关NPC在场）
  → 裴嘉应对话窗口（每阶段出现3–4次）——深谈可恢复will +2
  → NPC事件（随机，根据阶段和Flags加权）
  → 若有权限：裴嘉应笔记本偷看窗口
  → 若 wrote_journal = true：记录当日行为原子

深夜（突发事件）
  → 通常平静（70%概率：无事，仅日志条目）
  → 事件池（30%概率：丧尸探查、NPC危机、感染症状、记忆/梦境）
  → infection >= 7 的深夜：可能触发「镜中第三人」场景
```

## 9. 第四阶段·审判之秋（第271–365天）

**主旨：** 收束。每个选择现在都有复利。

### 9.1 ✨ FIX — 百日围攻防御指数数学修正

**v2.0问题**：围攻期间 security -3/天，60天（Day 271–330）= -180，超过上限100，导致任何玩家在Day 304必然基地沦陷，数学上不可能在停火窗口前生存。

**v2.1修正**：取消「每日被动扣减」机制，改为**事件驱动型扣减 + 战时紧急修补系统**。

**新围攻力学：**

```
被动扣减：security -1/天（不再是-3）
里程碑围攻事件：每10天触发一次（Days 300, 310, 320），每次 security -10
              战斗选择可影响具体扣减值（+/-5）

战时紧急修补行动（新增）：
  消耗：iron_plate ×2 + duct_tape ×1（或 5单位食物替代）
  效果：security +20
  限制：每个里程碑间隔最多使用1次（防止无限刷回）
```

**数学验证（从fortress 100开始）：**

| 事件 | 天数 | security变化 | 累计security |
|------|------|------------|------------|
| 进入第四阶段 | Day 271 | — | 100 |
| 被动扣减（29天） | Day 271–299 | -29 | 71 |
| 里程碑事件1 | Day 300 | -10 | 61 |
| 被动扣减（9天） | Day 301–309 | -9 | 52 |
| 里程碑事件2 | Day 310 | -10 | 42 |
| 被动扣减（9天） | Day 311–319 | -9 | 33 |
| 里程碑事件3 | Day 320 | -10 | 23 |
| 被动扣减（9天） | Day 321–329 | -9 | 14 |
| 停火窗口开启 | Day 330 | — | 14（仍存活！） |

**若玩家使用战时修补（每次事件前修补一次）：**

| 使用修补 | 消耗 | security修复 | 净效果 |
|---------|------|------------|--------|
| 修补1（Day 299） | iron_plate×2 | +20 | 事件后 security = 71 |
| 修补2（Day 309） | iron_plate×2 | +20 | 事件后 security = 82 |
| 修补3（Day 319） | iron_plate×2 | +20 | 停火时 security = 53 |

**设计意图**：围攻是消耗战，不是数学必败局。玩家需要在Phase 2–3囤积修补材料，才能在Phase 4有足够的战时紧急修补资源——这将第一、二阶段的「垃圾佬改装」系统与第四阶段的生存直接连接起来。

```
  A-2 基因阻断剂           priority = 20
  A-1 凡人钢铁黎明         priority = 21

  记录者                    priority = 40  ← 最后检查，条件最宽松
  BE-3 第364天              priority = 41
```

### 11.2 边界冲突解法

**冲突案例**：infection=4（幸存者） + `base_factory` + 改造>=3（F-1条件中的机械要求）

**解法**：F-1条件中**必须同时满足** `superpower_awakening = true`（infection 5–7且will>=8触发），infection=4时不可能有此flag。

因此：
- infection=4 + 大量改造 → 走幸存者路线，按第4层判定
- infection=5–7 + 大量改造 + superpower_awakening → 走觉醒路线，按第3层判定

**通用规则**：当infection值与transformation path flag不一致时（极少情况），**以flag为准**。flag是明确的玩家历史记录，infection值在极端情况下可能因药物/修补被降低，flag不会随之消除。

### 11.3 代码层面说明

在 `endings.json` 中，每个结局的 `priority` 字段按照以上金字塔数值设定。

在 `endingEvaluator.ts` 的 `checkForEnding` 函数中，endings按 priority 升序排列，第一个满足条件的结局立即返回——金字塔越底层（数字越小）越优先。

```typescript
// 当前实现（src/engine/endingEvaluator.ts）已经是正确的：
const sorted = [...endings].sort((a, b) => a.priority - b.priority)
for (const ending of sorted) {
  if (evaluate(ending.conditions, state)) return ending
}
```

只需确保 endings.json 中的 priority 值与本章金字塔一致即可。

## 12. ✨ NEW — 裴嘉应笔记本插值模板规范

**v2.0问题**：「根据前1–3天的行为动态生成」如果为每种行为组合独立写文本，内容量会以指数级增长（8种行为 × 3种语气 × 3天历史 = 数百种组合）。

**v2.1修正**：定义行为原子（Behavior Atoms）+ 语气修饰符（Tone Modifier）的模板拼接系统。

### 12.1 行为原子（Behavior Atoms）

每天黄昏结算时，自动设置以下一日行为标记（非持久化flags，每日清零）：

| 原子名 | 触发条件 |
|--------|---------|
| `atom_overclocked` | 当日使用超频操作 ≥1次 |
| `atom_overworked` | 白天行动选择了「建造」或「搜刮」连续3天以上（`excessive_exertion`累积） |
| `atom_rested` | 白天行动选择了「休息」 |
| `atom_journaled` | 白天行动选择了「写日志」 |
| `atom_helped` | 白天外交行动中帮助了NPC |
| `atom_fought` | 触发了战斗事件 |
| `atom_researched` | 白天外交/研究行动 |
| `atom_crafted` | 黄昏完成了一次改装 |

### 12.2 语气修饰符（Tone Modifier）

根据当前 `trust` 值选择语气：

| trust范围 | 语气 | 修饰效果 |
|---------|------|---------|
| trust >= 15 | 温情（warm） | 主语改为「他」（不再是「样本A」），句尾偶发温度 |
| trust 8–14 | 中性（neutral） | 标准临床语气，「样本A」，观察句式 |
| trust < 8 | 冷静（cold） | 纯数据记录，无主观色彩，偶尔有隐忧 |

### 12.3 模板结构

每条笔记本条目由以下部分拼接：

```
[基础观察句] + [条件插入段落（若对应atom=true）] + [语气修正尾句]
```

**基础观察句库（按感染值段）：**

| infection范围 | 基础观察句 |
|-------------|----------|
| 0–2 | 「今日常规检查。右手中指情况稳定。」 |
| 3–4 | 「右手指腹皮下有轻微异常，颜色偏深约0.1mm范围。未见主动恶化。」 |
| 5–6 | 「样本A今日右手应力感知已有明显变化，但行动控制正常。」 |
| 7–8 | 「边界区间。今日观察到两次行为延迟，疑似决策回路干扰。」 |

**条件插入段落（若对应atom激活）：**

| atom | 插入段落（中性语气版本） |
|------|----------------------|
| `atom_overclocked` | 「今日使用异能辅助{count}次。右手指腹静脉充血，持续约{minutes}分钟。他试图用袖子挡住我。」 |
| `atom_overworked` | 「连续工作时长超过正常阈值。生理指标：{symptom}。精神状态：表面稳定，眼部微颤未停止。」 |
| `atom_rested` | 「今日样本A选择休息。这在过去{days}天里是第一次。值得记录。」 |
| `atom_journaled` | 「今日他在写东西。我没有看是什么。我没有偷看。（备注：我有一点点想看。）」 |
| `atom_helped` | 「今日协助了{npc_name}解决了{problem}。道德判断中枢功能完整。」 |
| `atom_fought` | 「今日发生遭遇战。样本A的反应速度比上周快了约{percent}%。我不确定这是不是好事。」 |

**语气修正尾句（warm语气示例）：**

> *「他今天比平时早了半小时回来。我没有问他去哪了。」*

**语气修正尾句（cold语气示例）：**

> *「样本A今日行动轨迹无异常。情感信号：微弱，但存在。」*

### 12.4 实现建议

裴嘉应笔记本不需要后端AI生成——全部条目由**模板字符串拼接**在前端完成：

```typescript
// src/engine/notebookGenerator.ts（规划文件）
function generateNotebookEntry(
  state: GameState,
  atoms: BehaviorAtoms,
  tone: ToneMod,
): LocaleString {
  const base = selectBaseObservation(state.stats.infection)
  const inserts = collectActiveAtomInserts(atoms, tone)
  const tail = selectToneTail(tone, state)
  return {
    zh: [base, ...inserts, tail].join(''),
  }
}
```

内容复杂度由此从「数百种文本组合」降低为「约30个模板片段」，完全在独立开发者可控范围内。

### 14.3 内容写作六原则

**1. 每一天都有代价。**
时间消耗不是惩罚，是游戏告诉玩家生活需要时间的方式。不要让任何行动免费。

**2. 裴嘉应不是奖励。**
她的存在不会让事情变容易，只会让事情变得有意义。游戏中最难的场景应该涉及她在某件事上是对的。

**3. 感染从不自我宣告。**
永远不要写「你感觉到了病毒的力量」。
写「你在不看的情况下知道那颗螺丝已经松了」。

**4. 白大褂是不可知的。**
抵制解释它的冲动。裴嘉应的笔记本可以有理论。理论应该自相矛盾。

**5. 所有结局用同一种声音。**
每一个结局都用和开场场景相同的克制、实际语气写就。

**6. ✨ NEW — 信号要可侦测，不要可预料。**（v2.1新增）
Trust信号、派系伏笔、白大褂的出现——都应该是「事后回想起来，早就有迹可循」的，而不是「你一定能注意到，否则游戏不公平」的。粗心的玩家会被惊到，细心的玩家会有「果然如此」的满足感。两种体验都是正确的。
